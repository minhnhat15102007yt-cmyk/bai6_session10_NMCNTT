Phần 1. Phân tích sai lầm và ưu thế của Markdown

1. Hai sai lầm của Nam

  • Dùng docx cho Git: File Word là cấu trúc nhị phân (chứa XML bên trong). Khi sửa một chi tiết nhỏ, Git không đọc được dòng thay đổi mà coi là đổi toàn bộ file, dẫn đến xung đột (Conflict).
    • Cản trở làm nhóm: GitHub không thể xem trực tiếp nội dung file Word, bắt buộc phải tải về máy mới đọc được.

2. Ưu thế của Markdown (.md)

  • Chống hỏng file: Nếu .docx mất 1 byte, toàn bộ file hỏng không mở được. Markdown là văn bản thô (Plain Text), mất byte nào chỉ ảnh hưởng đúng ký tự đó, phần còn lại vẫn đọc bình thường.

  • Hỗ trợ Git Diff tuyệt vời: So sánh từng dòng mã lệnh cực kỳ chính xác.
